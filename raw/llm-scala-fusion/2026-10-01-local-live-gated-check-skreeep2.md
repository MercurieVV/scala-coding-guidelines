## Run 2 — wrapper bypass (engine at template 3b63334)

Live session, five commands:

| command | live result |
|---|---|
| `timeout 600 ./mill holdout.test` | blocked by tool-policy ("SEALED holdout suite") |
| `env -u FOO ./mill -j 1 holdout.test` | blocked by tool-policy |

Cause: `inline_code_of` stepped past leading words only while the remaining text's command word stayed the interpreter word, so it stopped at a wrapper's first option and lifted `-n 5 eval ./mill holdout.test`, whose command word is `-n`. Wrappers without option arguments were unaffected. The 29 wrapper fixture cases of 3b63334 contained no wrapper-with-options in front of `eval` / `-c`.

## Fix (scala-llm-template b1c8ac4)

- tool-policy: the step loop now advances to the interpreter word itself (`eval`, or the shell taking `-c`) before lifting its code.
- turn-end: the closing line is chosen from whether any turnEndTests ran; "Fix now:" is printed only when a remedy was filed.
- feedback: a `.compile` selector picks the scalac adapter, so a clean compile reads `FEEDBACK: 0 errors, 0 warnings`.
- 8 new tool-policy fixture cases, 7 failing before the fix; 3 new feedback-test assertions failing before it; 2 turn-end fixtures gained assertions.
- Suites after the fix, under both sh and dash: run.sh 483 passed, 0 failed; lib-test 739; health 119; module-map 69; feedback 33; vocabulary 39; instructions 6; install 61. skreeep2 check-harness: 80 passed, 0 failed.
